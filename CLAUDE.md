## The project in three lines

Forme NURBS is a hard-surface modelling app (PC first, iPad later): an object is a list of features (Cube, Cylinder…) combined in order (Add = union, Carve = cut), built as exact B-rep solids by **OpenCascade** and shown as its mesh with its B-rep edges. The UI looks like Forme's « Établi » interface (floating islands, tool cards, one inspector, history strip), in English, dark, with the white accent.

11. **Direct fillet modifiers and tension** (asked 19 nov., 6 h 25: "En edge comme en point / CTRL maintenu : chamfer mode / SHIFT maintenu : tension set"; captures only). During a fillet drag (`update_round_drag(at, ctrl, shift)`): Ctrl held makes it a chamfer for this drag only (the top island's option stays); Shift held sets the tension instead of the size (on an edge fillet: up fuller, down flatter, 0.004 per point; on a sketch / path corner: the conic's middle follows the pointer along the line from its ends' middle to the corner, `corner_rho_at`). The tension is a conic's rho (0.05 to 0.95; 0 = circular, whose rho is `circle_rho(θ)`, 0.414 at 90°): `Round.tension` for a fillet step, `Profile.tension[i]` for a corner; the op window has a Tension slider and Circular. A corner: `Cut.rho`, a rational quadratic (`cut_points`, `CutKind::Conic`, `focc_prism_cut` ck 3). An edge fillet: after OpenCascade's fillet, `Shape::fillet_tension(&[(tag, rho)])` (`focc_fillet_tension`, several fillets in one go, each its tension) replaces each round face by a conic one: a cylinder by the conic swept along its axis (`Geom_SurfaceOfLinearExtrusion`), a torus (a fillet along a circle: a boss's top or foot, a rounded corner of a chain) by the conic turned round its axis (`Geom_SurfaceOfRevolution`, the axis X × Y: OpenCascade's torus frames may be left-handed); faces built by hand, the contact edges kept (their pcurves moved), each end section remade as the conic moved onto its plane. An end may lie on a flat face (square or oblique to the axis), on two flat faces (a chamfer and a side: the vertex between them moved onto the new surface along the edge leaving there, `GeomAPI_IntCS`), on another conic face of the same tension (a mitre: the section's own plane), or on a **sphere corner** where three straight fillets of one tension meet: the corner is remade as a degenerate rational Bezier patch through the three new ends (poles P P P / Mb K Mc / Q Ma R, weights wi wj, K = Mb + Ma − Q; a sphere's eighth again at the circle's rho), tangent to all three (a fully rounded box takes tension, test `tension_rounded_box`, shot `tension-box`). What cannot (an end on a round face, a blended corner of two sizes, a three-edge corner other than three equal straight fillets) stays circular and the model lists it ("tension on n of m faces"). In the build (`build::tension`, the round step): a blended fillet (`blend`) rebuilds the run circular, then every tension of the run is put back with its own, in one call; when that loses a tension that took before (`Stage.conic`) or this step's own, the fillet made on its own next to the conic faces is taken instead if it loses fewer. Limit, geometric (not the algorithm): a chamfer or fillet running along a tensioned fillet's end (its chain continues round the conic) cannot be bigger than the conic's tightest radius of curvature: for a flatter one (rho < 0.5) at its ends, 2 r w² with w = rho / (1 − rho) at 90° (on the test part 0.57 mm at tension 0.2 with a 4.6 mm fillet, 2.3 at 0.35), for a fuller one in its middle; it stops there as any fillet too big. Tests `edge_tension`, `edge_tension_test_part`, `corner_tension`, `tension_boss_ring`, `tension_boss_foot`, `tension_run`, `tension_oblique_ends`, `tension_next_fillets`, `tension_after_corner`, `tension_rounded_box`, `tension_probe` (ignored, prints); shots `tension`, `tension-box`.

## Commands

```bash
export FORME_OCCT_ROOT=/path/occt-7.8                        # an installed OCCT 7.8 (lib/ include/); on PC use --features builtin instead
cargo test --release -p forme-occt --no-default-features      # the C layer: cube − hole, fillet, face tags, topology
cargo test --release -p nurbs-kernel --features occ           # the document → B-rep build, caches, skip, encode / decode
cargo build --release -p nurbs-kernel --features occ          # the kernel process forme-nurbs-kernel
cargo build --release -p nurbs-kernel --features builtin      # same, building OpenCascade from source the first time (6 to 20 min, cmake + C++ compiler)
cargo build --release -p nurbs-app                            # the app forme-nurbs and the capture harness forme-nurbs-shot
cargo run --release -p nurbs-app --bin forme-nurbs            # the app (finds target/release/forme-nurbs-kernel next to it, or FORME_NURBS_KERNEL=path)
./target/release/forme-nurbs-shot /tmp/x                      # every capture scenario on the test part; prefix filter: empty, part, move, create, quick, sketch, edges, faces, blend, quads (quads-corner: fillet corners, the large fillet), comp (component moves, vertex fillet), path, pen, rdrag, tension (tension-box: the rounded box), extrude-curved, marquee, direct, inset, help, outliner, qwer, marking, fields, materials, history, knife (knife-curved: across the boss's side), remesh, snap
```

`forme-nurbs-shot` runs the real app headless (egui + wgpu, real kernel process, real mouse events). It accepts a software GPU (lavapipe / llvmpipe) and writes full-quality PNGs at 1600×900 points, scale 2. Use it to check every visual change before showing it.

The window title shows the version, branch, commit and commit date (`crates/nurbs-app/build.rs`, `nurbs_app::version_title()`): check it before saying which version Romain is running.

## Code map

- `crates/forme-occt`: our thin C layer over OpenCascade (`cpp/forme_occt.cpp` + safe Rust wrapper). Primitives, transforms, booleans, fillets / chamfers by edge index, meshing. Every OpenCascade exception is caught and returned as `Err`; only `opencascade::handle<T>` is used (the `Handle_T` aliases break under MSVC). **Face tags**: each face carries an `i64` tag that booleans, transforms, fillets and chamfers carry to the faces they make (`carry_tags`, history `Modified`); new fillet / chamfer faces get the `fresh` tag. `Shape::topo(defl, angle)` returns in one buffer the faces (tag, surface kind, plane point / normal, axis, radius), the mesh with a face index per triangle, and the edges (index, the two faces, kind, seam, polyline). OpenCascade is built by `occt-sys` (feature `builtin`, cached in `target/OCCT`) or taken from `FORME_OCCT_ROOT`.
  Quads: `quad_topo()` (each face's wires in order, each edge's ends, kind and samples), `edge_on_face(face, edge, reversed, t)` (points and the face's uv along an edge), `face_eval(face, uv)` (points and outward normals).

## Rules that are easy to break

- **No SDF, ever, on this branch**: the part on screen is always the kernel's mesh. While the kernel computes, the previous mesh stays, with the moved or created shape drawn as an outline.
- Picking and selection go through the kernel's faces and their tags (`Model::faces[f].tag`), never through a field or a guess from the shape list.
- A tag is `(feature << 16) | sub`; any new primitive must tag all its faces in `nurbs_kernel::build::sub_of`. Edges are never named by their index in OpenCascade's edge map (it changes with every build): always by the tags of their two faces.
- Both sides of the kernel protocol (`proto.rs`, `model.rs` encode / decode) change together; the kernel process is rebuilt with the app.
- Never commit `target/` or `shots/replay/frames/`. Never run `cargo fmt` on the whole tree.
